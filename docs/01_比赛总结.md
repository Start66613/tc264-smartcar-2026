> 2026-10-05 第一行代码 → 2026-10-11 比赛 **40 秒**

## 三、七天做了什么

### 阶段一：从零到"能跑"（10-05 → 10-06）

- 起点：完全不会嵌入式。第一天先把**屏幕诊断页**做出来——因为"看不见车在想什么"是最大障碍。
- 三个当天就撞上的坑，全部是**工程性问题**而非算法问题：
  - 库函数 `adc_convert` 在中断里死等 → 系统卡死（v013 加超时）
  - 屏幕越界断言 → `while(1)` 死机 → PWM 保持 → 车乱跑（v014）
  - 宽度读数破百导致绘制越界（同一个坑的另一面）
- 关键决策：**先做"可观测"，再做"控制"**。这个顺序在后面救了很多次。

### 阶段二：速度闭环与 IMU（10-06）

- 编码器闭环一次成功，但目标值没标定 → 车变蜗牛（v031 回退）。
- **IMU 初始化顺序**：屏幕先 → IMU 后，才不花屏/不失联（v028）。这个坑花了整晚。
- 大环判据从"宽度三段式"一路试到"里程 + 视觉混合"，最后被证明**视觉判据在普通弯道会误触发**。

### 阶段三：换摄像头，视觉重建（10-07 → 10-09）

真正的转折点。CCD 换成 MT9V03X 后：

| 问题 | 根因 | 解法 | 版本 |
|---|---|---|---|
| 图像撕裂 | DMA 半帧快照 | DMA 完成中断内快照 | v079 |
| 方向反了 | 安装镜像 | `CTRL_MID_MIRROR` 翻转 | v079 |
| 蓝区被当白路 | 一级 Otsu 把蓝白合并 | **两级递归 Otsu**（亮类 >62% 再分一次） | v105 |
| 中线漂移 | 贴边行中点必偏 | 只用"双边都在画面内"的行做测量 | v104 |
| 路口中线闪烁 | 16px 边斑被当种子 | **种子资格闸门** + 路口顶住 | v106 |
| 路口折返 | `edge_mode==3` 未覆盖 | 重建须同时覆盖 edge3 | v107/v116 |

**这一步之后，车才第一次"看得懂赛道"。**

### 阶段四：锁定基线（10-10）

- v123 跑出 **39 秒**（大环模块关闭），锁定为 GOLDEN 基线。
- 用户当场定下铁律：**任何改动必须先有数据 + 理论 + 批准；一次只动一处；四门禁齐备才算数。**
- 这条规矩在此后 25 次烧录里，至少避免了 3 次"改坏了还说不清哪坏了"。

### 阶段五：攻环岛 + 比赛（10-11）

一天之内 14 个版本（v133→v148），是全程最激烈的一天：

| 版本 | 改了什么 | 结果 |
|---|---|---|
| v133 | 环岛状态机整体重写（点3武装→点2进环→点1退出） | 检测器 ±5px 就失效，首次实车未触发 |
| v134 | 检测器稳健化（30 变体 + 8 负样本参数搜索） | 能触发了 |
| v135 | 环内禁止左转 | 治住"往回跑"，但出环不能修正 |
| v141 | 左转协调（轻左放行/大左改右）+ 8s 保险 | **首次全程含环岛跑通** |
| v143 | 盲区降速 | **run12 完整成功轮**（46.9s，终点自停） |
| v146 | 弯道提速 | **比赛用版本** |
| v147/v148 | 阈值 60 + 顺序竞态补救 | 烧过，赛后按用户要求回退 |

## 四、三场关键战役

### 战役一：蓝白赛道（v104→v105）

**症状**：车在蓝区上"看到"一条中线，然后一头扎进去。

**误判**：一开始以为是阈值没调好，反复调灰度门限 —— 无效。

**真相**：一级 Otsu 在"蓝底 + 白路 + 黑胶带"三色分布下，只能分出"黑 / 非黑"，蓝和白被合并成同一类。所谓"中线"是蓝白边界。

**解法**：亮类占比 >62% 时，对亮类**再跑一次 Otsu**，得到"蓝 | 白"分界；同时把"逐行追中点"改成**左右边线各自分离 + 双边界连续性**。

**证据**：同一帧 `measured` 从 7 → 46（可信测量翻 6 倍）。

### 战役二：环岛（v133→v148）

**症状**：能识别、能进环，但出环姿态差、偶发"不进环"、环内盲区飞出。

**三层问题，逐层剥**：

1. **检测层**：检测器只认标定单帧，±5px 就失效 → 30 个平移/亮度变体做参数搜索（v134）。
2. **控制层**：环内允许左转 → 视觉锁左侧线 → 满左往回跑 → 加"左转协调"（v141）；出环右偏想修正却被反打 → 阈值 80→60（v147 的思路，已被 v146 之前的版本验证）。
3. **时序层**：口特征比武装特征先凑齐 2 次确认 → 被丢弃 → 武装后口再也不出现 → 全程卡"武装"（v148 修）。

**代价**：v144/v145/v147/v148 四个版本烧了又退。**根因是"一次改多处"和"没有先复现再修"。**

### 战役三：盲区（v142→v143）

**症状**：车在某个路段突然加速、舵角冻结、冲出赛道。7 轮里 6 轮死在这里。

**关键证据**：9 张自动存帧，直方图高度一致：

```
过曝（≥240）  55% ~ 80%
中间调        26% ~ 37%
暗部（<100）  < 1.5%
```

**结论**：那段画面里**真的没有线**——不是阈值判错，是物理上信息缺失。所有"调阈值/换算法"的方向都是死路。

**解法**：连续 ≥2 拍无有效线 → 强制压爬行档（每拍 -160 → 450）、跳过 PI 积分；线一回来立刻恢复。

**验证**：run12 里两次触发（f368、f738），速度从 1956/1764 压到 672/444，稳住后恢复，最终完赛自停。

## 五、差在哪（诚实差距分析）

| # | 差距 | 后果 | 严重度 |
|---|---|---|---|
| 1 | **只做了右环** | 赛规 A–D 四环均须入环绕行；左环未实现 | ★★★ |
| 2 | **长盲区只能"减速熬过去"** | 不能真正"看见"，只能保证不飞出去 | ★★☆ |
| 3 | **环岛成功率不稳** | 最后 6 轮只有 2 轮完整跑通（33%） | ★★☆ |
| 4 | 锁舵机僵持未修 | 全白/非全白计数器互相清零 → 7.6 秒僵持 | ★★☆ |
| 5 | B-1 缺陷未修 | 丢线计数被 ISR 压成布尔 → "挣扎"分支不可达 | ★☆☆ |
| 6 | 相机偶发无信号 | 烧录后 `dma_int=0`，重启/插线后恢复 | ★☆☆ |

### 遗留问题详情

**① 锁舵机僵持（run13 f418-534）**
- 现象：444 爬行 + 舵角冻结 + 4.4° 缓漂，持续 7.6 秒，最后人工停车。
- 根因：**全白帧的 100 帧停车保护** 与 **非全白帧的 25 帧保护** 交替触发，两个计数器互相清零，永远攒不满。
- 候选修法：A 统一盲区计时 / B 超时主动慢转 / C 不修。**未决策。**

**② B-1 丢线计数**
- `line_out_lost_count` 被 ISR 直接赋 0/31（布尔化），"挣扎"分支永远不可达。
- 影响：诊断失真 + 一段死 UI 分支。

**③ 相机无信号**
- v148 烧录后连续回读：`frame_seq=0 / dma_int=0 / lost_flag=1`。
- 已核验与固件无关（v148 与 v147 差异仅在 `big_ring.c/h`）。
- 处置：断电重启 + 查排线。**未闭环。**

## 六、如果重来（按优先级）

1. **第一天就做记录通道。** 记录是 v130 才加的，也就是说前 25 个版本全靠肉眼看车。有了记录，调试效率至少翻倍。
2. **先跑通整圈，再加功能。** v123 的 39 秒基线让后面所有改动都有了"是否变差"的判据。没有基线时，改完只能凭感觉。
3. **环岛状态机从"顺序无关"设计。** 特征是"事件流"，不是"剧本"；用 1.2 秒时间窗兜住乱序，比事后打补丁便宜。
4. **盲区兜底属于"第一天就该有"的安全网**，不该等到 6 次失败之后才做。
5. **一次只动一处，并且先复现。** v144/v145 的来回，本质是"改了两处，不知道哪处起作用"。
