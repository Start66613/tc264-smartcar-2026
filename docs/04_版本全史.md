## 三、被否决/回退的版本（同样重要）

| 版本 | 想法 | 否决原因 |
|---|---|---|
| v124/v125 | 白面顶住 / 统一"保持方向" | 用户实车判定"S 弯还是不能跑，改废了" |
| v135–v140 | 禁左 / 停用路口 / 舵量增强 | 单点有效但互相牵制，最终从 v134 重新起底 |
| v144 | 环内盲区注入合成线 | 一次改两处，实车失败无法归因 |
| v145 | 阈值 60 | 与大回退一起作废（后来证明方向对） |
| v147 | 阈值 60 + 弯道二次提速 | 比赛后用户指定回退到 v146 |
| v148 | 顺序竞态补救 | 修的是真 bug，但赛后回退 |

**教训**：**回退不是失败，是控制风险。** 198 个版本里，有 30+ 个被回退——正是这些回退保证了比赛时车上跑的是"验证过的那一版"。

## 五、怎么用这些版本

### 看某版改了什么

```bash
cd versions/VisionTrack
diff -u v145_leftcoop_tighten_91E8FA16_flashed/code/track_core.c \
        v146_corner_speed_C4E5B2DC_flashed/code/track_core.c
```

### 回退到某一版

```bash
cd D:/智能车/firmware/TC264_VisionTrack/code
cp track_core.c.bak_v146pre track_core.c     # 回到 v143
python ../../scripts/build_tc264_servo_check.py TC264_VisionTrack TC264_VisionTrack --no-wipe --no-indexer --fresh-workspace
python ../../scripts/check_expression_hex.py --project TC264_VisionTrack
# 期望 SHA = BE6E1A07...
```

> 注意：`.bak_vXXXpre` 是"改之前"的快照，不是"改之后"。
