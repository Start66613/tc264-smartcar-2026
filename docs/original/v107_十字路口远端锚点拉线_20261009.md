## 一、现场反馈

> "在十字路口，还是全白。但是我看你能不能不止看前面一点，能不能稍微往远处看点看远处的中线，有个参考。"

v106 已经把"拿贴边小白斑当种子"这个坑堵住了（路口不再闪），但路口**仍然看不到线**。用户要的是：**别只看近处，往远处看**。

---

## 二、先把路口那一帧整幅画出来（`scripts/ascii_frame.c`）

光看数字看不出来，直接把二值图渲染成 ASCII：

```
y=28  .................................############################.................................
y=30  .................................############################.................................
...
y=46  ............................######################################............................
y=47  ####################################################################################...###..##
y=48  ##############################################################################################
...
y=110 ##############################################################################################
```

**结构一目了然：**

| 行段 | 内容 | 对算法的意义 |
|---|---|---|
| **y=28..46** | 一条**干净的路面横截面**：x=66..120（中心 **93**），左右都是黑的 | ← **这就是"远处的中线"**，是真实可见的路面 |
| y=47..110 | 一整块白（横向道路铺满，宽 188） | 底部 14 行全被盖住 → **底部种子无从取** |

**所以 v106 的行为是：底部没有种子 → 直接"顶住上一帧中心"画一条竖线 → 远处 y=28..46 那条真实可见的路面被完全忽略。**

## 三、还有一个更隐蔽的坑：v106 的路口"顶住"在屏幕上根本不显示

`code/track_adapter.c`：

```c
line_out_center = frame.valid ? frame.mid*128/188 : -1;
```

v106 在路口走的是 `hold` 分支，**`v->valid=0`** → `line_out_center = -1` → **屏幕上没有黄点中线**。
这就是用户说的"还是全白"——不是白得看不见，是**根本没画线**。

> 教训：`valid` 不只表示"线可不可信"，还直接决定**屏幕画不画**。凡是"我想让用户看到我还在跟线"的状态，`valid` 不能是 0。

## 四、国赛怎么做的（本轮唯一参考依据）

查挖矿报告里两家同平台/同名次的实现，**都是同一招：不造几何，拉直线。**

| 来源 | 函数 | 做法 |
|---|---|---|
| NEFU（`A_轮次2_NEFU八邻域双栈巡线与中线.md:283-311`） | `connect_line(x1,y1,x2,y2,way)` | 「从起始点往下**拉一条补线**」补全一边；旧版三叉口 `lian_xian_zhi(边线,行,目标列,...)`「**拉直线补全**」，配 `HOW` 状态机（HOW=1 十字补线 / 3 右斜 / 4 左斜） |
| NEFU 1748–1756 | 缺口定位 | 在固定列上从上往下扫"白·白·黑·黑"模式，**找横向白带的上沿** |
| HammerTa（`A_轮次2_环岛补线族全族.md:127-128`） | 两点反解斜率 | `k=(star_col-Round_L.Col[0])/(star_row-Round_L.Row[0])` —— **用两个已知点反解斜率再沿直线铺点**，专门用于"整块图像缺失"的场景；并把补出来的点用**另一种颜色**画出来，和"真看到的"区分 |

NEFU 报告第 311 行的结论原话：**"环岛用'换线/拉线'而不是'造几何'"** —— 十字同理。

## 五、v107 改动：第 2b 遍「远端锚点 + 拉线补全」

`code/track_core.c`，插在第 2 遍（种子跟踪）与第 3 遍（测量+插值）之间。
**只在"确实存在横向铺满的白带"时才启用**，避免急弯/岔口把另一条分支误当远处路面：

```c
if(ok_rows<(int)VT_OK_MIN && full_rows>=(int)VT_FULL_MIN_ROWS){
 /* ① 从上（远）往下找第一条**可信的路面横截面**当远端锚点 */
 for(y=VT_ROW_TOP;y<=VT_ROW_BOT;y++){
  if(vt_sn[y]!=1)continue;
  l=vt_sl[y][0]; r=vt_sr[y][0];
  if(!vt_seed_ok(y,l,r))continue;        /* 复用 v106 的种子资格闸门 */
  fy=y; fl=l; fr=r; break;
 }
 if(fy>=0){
  /* ② 远端锚点本身是**真实测量**：从它向 y+（朝车头）延伸，双边界连续性照旧 */
  ...
  /* ③ 拉线：远端锚点 → 近端参考（上一帧中心），中间凡是还没有可信测量的行，
   *    沿两点直线铺点 → 新增行分类 VT_ROW_LINE */
  ny=VT_ROW_BOT; nc=(t->previous_mid>0)?t->previous_mid:fc;
  for(y=fy+1;y<=ny;y++){
   if(vt_trust(y))continue;
   vt_rowv[y]=nc+(fc-nc)*(ny-y)/(ny-fy);
   vt_rowc[y]=VT_ROW_LINE; ok_rows++;
  }
 }
}
```

配套改动：

- 新增行分类 **`VT_ROW_LINE`**（`track_core.h` 枚举，插在 `VT_ROW_CLIPR` 与 `VT_ROW_FULL` 之间）；
- `vt_trust()` 上界由 `<=VT_ROW_CLIPR` 改为 **`<=VT_ROW_LINE`**；
- 第 3 遍里 **`VT_ROW_LINE` 计 `modeled` 不计 `measured`**（它没有真实边界，只是几何外推）——
  这样 `modeled>=24` 仍会 `degraded=1`，路口照样限速 320 通过。

**为什么远端锚点必须是"真实测量"而不是也当补线**：y=28..46 那条是**算法真的看到了左右边界**，
把它计入 `measured` 之后（实测 19 行），屏幕/控制/日志三处都能看出"这次不是硬顶的"。
