# v97 循迹代码复核与开源竞赛代码对照

复核日期：2026-10-08。仅分析和主机复现，未修改、构建或烧录车上工程。

**主要问题在视觉信息丢失、未启用的环岛分支和控制安全链，并非再调几组 Kp/Kd 就能消除。** 摄像头能够采图，不代表有效道路已经正确进入控制器。

## 版本范围与证据

入口工程为 `firmware/TC264_Senior6_RingDiag`。复核开始时冻结 `code/`、`user/` 到本目录 `snapshot/`，其中 PID.c SHA256 为 `4DA7B757FAC9340A4A47EC035CABC876FFF0D4DE3AAFE21F9DC70BD57467FE7D`，含 v097 指纹参数、`RING_ENABLE=0` 和临时 PROBE 常量。

**读取期间 WorkBuddy 又改写了当前工程与构建日志。** 22:05 归档中的 PID.c 实际含 v098 活跃 `rngf_*` 分支，SHA256 为 `9235F094F2F1617FD056AF7A0B03A88F57A7C3D3428721B99D9D4FD4E57BB74F`。不能用该归档/最近 HEX 冒充已冻结 v97 的运行版本。报告只针对 v97 快照；v98 需要另做同样的版本绑定与验证。之前“源码与板上版本对应”的初步判断已纠正。

本目录 `source_manifest.json` 固定各业务文件哈希；`flashed_PID.c` 保存读取到的归档内容，名称仅表示从烧录日志关联归档取出的源文件，不表示本轮回读了芯片。

复现脚本 `reproduce.py` 编译实际 PID、cam_image、cam_line、finish_line、control_time 代码。`snapshot/` 保留原 GBK/行尾字节；`host_source/` 仅把 CRCRLF 转为正常行尾、GBK 转 UTF-8，供 GCC 和阅读使用，没有修改算法。下面 PID.c 引用使用这份可读投影；cpu0_main.c 保留实际可读行号。未把历史其他 HEX 的跑车日志当作 v97 实物验收。

## 确定缺陷，按处理优先级

### P0：没找到道路也会生成“有效居中线”，丢线保护失效

`host_source/cpu0_main.c:2745` 将无效的 `cam_mid_near=-1` 改为画面中心；2760 行随后人为画出中线两侧各15像素的白带。旧控制器看到的是有效白带，不是原始失败结果。

实际黑画面复现：`cam_mid=-1, cam_rows=0`，却生成 `fake_white=21`；40次控制后 `lost=0`，两轮 PWM 仍为 `800/800`。这是主机代码复现，不是断开实车相机试验。没有必要靠试撞确认这条控制路径。

另外 `cpu0_main.c:3176` 只有新相机帧才调用控制器；画面完全停止时则根本不调用丢线计数，最后的非零 PWM 可以一直保持。需要**独立于图像算法和显示刷新的帧龄停车**。

处理：保留有效性/置信度、最后有效帧时间；无可靠道路不能替换为中心；超时硬置双轮0，并要求人工重新启动。

### P1：v97 新增环口指纹和350°兜底整个未编译

`host_source/PID.c:315`：`RING_ENABLE=0`。指纹参数、计数和350°分支在 `#if RING_ENABLE` 内。预处理结果中 `ring_fp_cnt/ring_fp_yaw0` 都不存在。

指纹设置为左900/右300，并累计模拟转角，仍 `ring_mode=0`；v97 注释描述的修复不能影响车。活跃的是另一套旧大环/CRING路径。

**不能只把开关改成1就认为修好了**：该旧分支环内直接把偏差定为±0.85，经PD/限幅会接近满舵，没有沿实际边线调整半径；350°清掉状态也不等于选择了正确出口。

处理：合并为一套元素状态机，明确“发现入口—经过第一口—入环—沿外/内边跟踪—识别出口—确认出环”，每阶段有真实路径输出和超时保护。

### P1：二维图被压成固定宽白带，终点与旧宽度出环条件失去输入

`cpu0_main.c:2751` 的桥接只保留一个中点，把道路宽度、多个白段、暗缝、斑马线全部抹掉。`DetectFinishLine(image)`（3329行）收到同一条合成白带。

同一合成斑马线测试：用真实二值扫描行喂原终点函数，3次可得到 `raw_row_detect=1`；经过目前桥接则 `bridge_detect=0`。合成图最多一条白带、两侧长黑区，无法提供要求的六条短黑纹。

`PID.c:126` 的 `BIGRING_W=200`，但输入总共只有128像素，因此大环宽度入口条件不可达；桥接后通常更只有20–21个白像素。`line_pick_left` 也没机会在多个出口段中选择，因为这些段已被删掉。

处理：转向用真实二维路径；终点用独立原始ROI；环岛用边界/角点/多段几何，不能让所有模块共用虚构的单条白带。终点连续帧计数还应放到新帧门控里，避免修复纹理后同一帧被主循环重复计三次。

### P1：平均轮速闭环无法发现单轮失效，PWM差速会改变平均动力

`PID.c:1086` 只用两轮反馈平均值调用一个 WheelPI，再给两轮同一基准PWM。堵转条件 `cpu0_main.c:3521` 也用两轮平均值。单轮0、另一轮920的反馈平均值恰好460，与当前直道目标一致；实际控制复现保持两路 `800/800`。按源码堵转条件，均值460也不会触发 `act<3`。

这次针脚配对本身正确：P02.7/02.6是物理左轮，P02.5/02.4是物理右轮。问题是新的反馈/差速结构，并非需要再交换线。

“差速对平均PI不可见”这条注释不成立：在基准PWM1000、舵量100时，内轮减2000钳为0，外轮加300为1300，平均输出650，不是1000。平均PI会响应随后的速度变化；一侧饱和、另一侧补偿会进一步改变车身旋转。

处理：按实际左右轮分别给目标并反馈，差速由转向角/车体几何或实测映射生成。单轮独立堵转与编码器失效停车，不用只看双轮均值。避免在原平均PI上再混贴另一套前馈。

### P1：停后重启仍带着上次环岛与转向状态

`PID_Reset` 没清函数内 `static d_filt`（PID.c:61）；RingReset/SpeedLoop_Reset也未清 `ring_cool_odo`、口沿里程和 `dz_last_out/dz_hold`。

复现：先制造一次导数后调用PID_Reset，零误差下一次PD输出仍是 `-5.0`（输出满量程±10）。环岛复位后仍保留冷却里程550000、上次口里程500000/490000；死区保持输出仍为4.0。下一次起跑里程却从0重新算，旧冷却里程可能挡住新一趟入口，旧舵量也可能重新出现。

处理：所有控制器状态必须归属于明确的结构体，并由同一个启动/停止复位入口清零；滤波器、元素冷却、上次口、有效性、终点计数一起重置。

### P1：急停实际是“松开按键触发”，且依赖显示主循环

`cpu0_main.c:1800` 按下只置 `pressed=1`，1803行松开并消抖后才返回事件。主循环处理事件之前还有绘图、相机和外设工作；运行时20.6换页/记录页等整屏刷新也是同步的。控制函数自身在 `PID.c:1155` 又直接写屏幕。

因此不能宣称“按下立即急停”，也不能以一次正常试按证明任意卡顿状态都能及时停。

处理：原始停止电平由固定周期任务优先处理；主循环/相机失联也强制0输出。控制器只发布快照，显示限频消费快照。

### P2：环心HOLE把外侧背景暗区当成内部环心

`cam_line.c:67/77` 的 `dark_max` 含左/右画面外侧暗区；221行却拿它判断两条白带之间的暗区。测试白段0..75、85..140时，内部暗区只有9像素（小于阈值25），外侧暗区47像素，却得到 `detected=1`。

而主循环2831行又将 `HOLE OR WIDE` 合为同一个“大片白”口标志，丢掉方向和原因，旧CRING只计无→有的沿变。局部弯道、画面裁切和背景变化都可能与环口混淆。

处理：只计算指定白段之间的内部暗区；多行连续边界缺失、角点及另一侧直边共同判定，保留左右方向和各特征置信度。

### P2：虽有20ms测速归一化，控制时基仍随界面和帧率变化

编码器/IMU在主循环3371行“超过20ms就读”，速度PI又等新图像帧才使用该采样。计数已按实测dt归一到20ms，这是正确改进，但 PI 积分每次仍按固定增量加一次、转向D项也没有dt。变更页面、帧率或耗时会改变实际闭环更新频率和滤波相位。

转向链还叠加±30跳变限幅、0.6/0.4中心低通、0.5/0.5导数滤波、死区保持、四样本陀螺滤波；并非每层都错误，但没有统一的延迟预算。不能只凭“国赛用了滤波”层层叠加。

处理：固定周期执行轮速/安全控制；新帧发布带时间戳的道路结果；显示低优先级。视觉前瞻与舵机/速度参数需按本车安装和采样单位标定。

## 与开源竞赛实现的具体区别

- **HammerTa TC264四轮**：`CODE/inti.c:52` 设5ms控制任务，`USER/isr.c:28` 调Control；`CODE/motor.c:246` 先算左右目标，293行分别做左右反馈PID。v97目前是显示循环顺便采样、单个平均PI再贴PWM差速。这些架构可以借鉴，5ms和增益不能直接照搬。
- **SJTU AuTop视觉**：`Project/USER/src/main.c:532` 开始分别找左右边界，做透视/去畸变、滤波、等距采样、局部角度与角点、中线重建；429行几何前瞻转向。v97虽做多行加权，最后只留下一个像素中点，没有相机几何标定、路径曲率和明确边界身份。
- **AuTop圆环**：`Project/CODE/circle.c:23` 用单侧L角点加另一侧直边检测；左右环都有BEGIN/IN/RUNNING/OUT/END，切换跟踪边并验证恢复。v97没有一套活跃的对等流程，转角到350/360°也只是状态超时，不是出口路径。
- **AuTop十字**：`Project/CODE/cross.c:51` 双角点进入十字，远近边线切换和恢复确认。v97没有独立十字状态机，宽区只会与环特征混在一起；最大白段/最近白段不能保证“交叉直行”。

参考项目也有缺陷，不能因“国赛”二字就整包替换。例如先前已记录AuTop右手局部阈值邻域边界保护不足；它的标定表、车辆尺寸、速度单位也属于原车。这里只比较可用架构，不保证原仓库原封不动即可跑本赛道。

## 建议顺序

1. 先固定版本、源文件及HEX绑定，修无效帧/超时/原始急停/完整复位。
2. 去掉虚构1D白带的通用桥接，让转向、终点、元素分别消费正确的二维数据。
3. 统一固定周期速度环和双轮反馈，低速确认转向、差速方向与堵转。
4. 再做左右边界、路宽/角点置信度、交叉直行、左右环分阶段换边、真正出口引导。
5. 最后对本车视角和电池做前瞻、曲率限速、起步及PD参数调试。

不建议同时提速、改PI、开固定满舵环模式再烧录。应逐层用真实相机帧离线回放，再实车低速确认。
