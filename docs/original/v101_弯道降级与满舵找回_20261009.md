# v101：弯道降级 + 满舵找回 + 内轮刹弯（治"弯道易停"）

日期：2026-10-09 17:16 ｜ 工程：`TC264_VisionTrack` ｜ HEX：`6869DFB1F55E…`

## 一、问题

板上跑 v100（VisionTrack + 丢线爬行找回）时，**弯道仍然容易停**。直道正常。

## 二、根因（本次定位）

`vt_analyze()` 的 有效帧判定是：

```c
v->valid = valid>=20 && near>=6 && wsum>0;
```

其中 `wsum` 只累加 **y∈[48,78]（画面中部/远端）** 的行。而**急弯时远端道路正好跑出画面**，
只剩画面**下方**（y≥90）的近处线 → `wsum==0` → `valid=0` → `vt_step` 判丢线 → 停车。

这解释了"直道好、弯道停"：直道有远端数据，弯道没有。

另外两个对照出来的差距（国赛代码）：

| 环节 | 国赛学长 6.0 / HammerTa | 我们（改前） |
|---|---|---|
| 丢线时 | **朝上次方向打满舵** + 降速保持前进 | 保持原舵量 + 爬行 ← **舵量不够，救不回** |
| 内轮差速 | 内轮几乎刹停（内外比可达 1:10）"咬弯" | 满舵时内轮只降 35% |
| 单边丢线 | 用另一边 + 道路宽度表 `TrackWild[row]` 半宽补线 | 无（整帧判有效/无效） |

## 三、改动（3 处）

### 1) 弯道降级控制 —— `vt_analyze` + `vt_step`

`track_core.h` 新增：

```c
#define VT_NEAR_ROWS     6u      /* 近处至少 6 行线才允许降级 */
#define VT_DEGRADE_SPEED 320     /* 降级时速度目标上限 */
```

`VTFrame` 新增 `uint32_t degraded;`。

`vt_analyze()` 在 `valid` 判定后加 else-if 分支：远端/中部看不到道路（`wsum==0` 或行数不够）
但近处仍有 ≥6 行线时，用**近处中心** `(nl+nr)/(2*nn)` 继续巡线并置 `degraded=1`。

`vt_step()` 入口由 `if(!v->valid)` 改为 `if(!v->valid&&!v->degraded)`，
并在 `target` 计算后把降级帧的速度压到 `VT_DEGRADE_SPEED` 以内。

### 2) 丢线满舵找回 —— `vt_step` 丢线分支

对齐国赛学长做法：丢线时**保留转向方向并把舵量推到满舵**（原来只是保持舵量），
双轮仍降到爬行速度继续找线。

```c
if(c->steering>0)c->steering=100;else if(c->steering<0)c->steering=-100;
```

### 3) 内轮差速加强 —— 差速分配

```c
// 前：inner=target*(100-abs(c->steering)*35/100)/100;
inner=target*(100-abs(c->steering)*55/100)/100;   // 满舵时内轮降到 45%
```

学长是 1:10（几乎刹停），我们保守取 45%，先观察实车再决定是否继续加。
