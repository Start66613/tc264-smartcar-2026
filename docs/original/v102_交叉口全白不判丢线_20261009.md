# v102：交叉口 / 环岛入口"整行全白"不再判丢线（治"一到交叉就停"）

日期：2026-10-09（未烧录，等遥控玩完） ｜ 工程：`TC264_VisionTrack` ｜ HEX：`3D5A19AF4E43…`

## 一、问题

实车反馈：**一到交叉（进圆环）就停**，问题很大。

## 二、根因

`vt_analyze()` 逐行扫描时：

```c
if(w<12||w>=VT_W-2)continue;      // ← 整行全白（w>=186）被直接跳过
```

**十字路口 / 环岛入口的图像特征就是"路面铺满整行"** → 每一行都被 `continue` 跳过
→ `best_l<0` → 该行不计有效 → `valid` 行数崩到 20 以下 → `v->valid=0`
→ `vt_step` 走丢线分支 → 连续 `VT_LOST_FRAMES` 帧后 **`VT_LOST` 停车**。

而且 `element()` 只在 `v->valid` 时被调用，所以**环岛状态机根本没机会启动**。

## 三、首个修复尝试踩的坑（值得记）

第一版直接改成"整行全白 → 沿用上次中心"，结果**主机测试立刻红了**：

```c
memset(image,255,sizeof image); vt_analyze(...); assert(!f.valid);   // 失败
```

因为"跑出赛道、对着白墙"也是整帧全白——**不能把"没路了"误判成"交叉口"**。

**区分判据**：交叉口是"**远处全白、近处有真实道路边界**"；跑出赛道是"**整帧都白**"。

## 四、最终改动（`track_core.c` / `track_core.h`）

1. 扫描时增加 `wide` 标记：某行出现 `w>=VT_W-2`（整行铺满）时置位。
2. 该行没有可跟踪段时，若满足全部条件才补线（沿用上一行中心直行，计入 valid）：
   - `wide` —— 本行确实是铺满的
   - `previous>0` —— 有中心参考
   - **`valid>0`** —— 本帧**已经跟踪到真实边界**（这一条就是防"整帧全白"的闸门：
     整帧白时循环从 y=110 起就没有任何真实行，`valid` 恒为 0，永远不会补线）
   - `wide_fill < VT_WIDE_FILL_MAX(50)` —— 补线行数上限，再兜一层
3. 新增宏 `VT_WIDE_FILL_MAX 50u`。

参考：国赛学长版 `CalculateCenterLine` 的「**全白 → 沿用上次值**」。
