# v100 丢线爬行找回（转弯略微出道不再停车）

日期：2026-10-09　工程：`firmware/TC264_VisionTrack`　基线：WorkBuddy v099

## 问题

v099 之后"画龙已解决、环岛在路上"，但**转弯略微出道就停车**（屏幕显示丢线），且停下后必须手动重按发车键。

## 根因

昨晚（10-08 23:27 起）的大重构按 `docs/v097_review_20261008/README.md` 的 P0 建议
"超时硬置双轮 0，并要求人工重新启动"实现丢线保护，但只做了"停"，没做"恢复"，且触发过严：

| # | 位置 | 行为 |
|---|---|---|
| 1 | `code/track_core.c` `vt_step` | `if(!v->valid){vt_control_stop(c,VT_LOST);return;}` —— **单帧**无效即停，无去抖 |
| 2 | 同上 `vt_analyze` | `valid>=20 && near>=6`，另有 `contrast<18` 直接返回、逐行链 `abs(center-previous)>35 continue`。转弯时线移到画面边缘/底部 → 链无法起种 → 单帧即判无效 |
| 3 | `code/track_adapter.c` | `if(controller.fault){line_ring_armed=0;track_fault=...;}` —— 任何故障都解除武装并锁存 |
| 4 | `user/cpu0_main.c` | `state==ST_RUN && track_fault` → `ST_STOP`、电机 0，屏幕 `ST_STOP` 映射为 `UI_ST_LOST` |

对照 v097 之前的旧版：旧代码把无效的 `cam_mid_near=-1` 替换成画面中心并人工造白带，
所以**从来不会判丢线**（正是 v097 复核的 P0：丢线保护失效）。本次重构删掉假白带是对的，
但把安全策略做成了"一帧就死"，属于修过头。

## 改动（本次）

仅动 `code/track_core.h` 与 `code/track_core.c`，不碰 `track_adapter.c` / `cpu0_main.c`，
停车语义保持原样（超时后仍停、仍要求人工重新发车）。

`track_core.h`
- 新增 `#define VT_LOST_FRAMES 10u`（连续丢线容忍帧数，20ms/帧 → 约 200ms）
- 新增 `#define VT_LOST_CRAWL  150`（爬行速度目标，输出约为其 3 倍 ≈ 450 raw）
- `VTControl` 新增 `lost_frames` 计数

`track_core.c`
- `vt_step` 丢线分支：`lost_frames` 未达 `VT_LOST_FRAMES` 时**不去停车**，而是
  保持上一帧舵量（不拿无效帧更新偏差/微分）、双轮**只降不升**地降到爬行地板继续找线；
  线一回到视野，下一帧即无缝接回正常控制并把计数清零。达到 `VT_LOST_FRAMES` 才判 `VT_LOST`。
- `vt_control_stop` 一并清零 `lost_frames`。

## 调参

- 还嫌停得早 → 调大 `VT_LOST_FRAMES`（如 15 ≈ 300ms）。
- 爬行太慢找不回线 → 调大 `VT_LOST_CRAWL`（如 200）。
- 两个常量都在 `code/track_core.h` 顶部，改完重跑 host 测试再构建。

## 遗留（本次未动，建议后续处理）

1. `code/track_adapter.c` 里 `line_out_lost_count = controller.fault==VT_LOST ? 31u : 0u` 是**常量 31**，
   而阈值 `LOST_STOP_LIMIT=8` / `LOST_GIVEUP=30`（`code/PID.h`）→ "丢线挣扎"那一级被整段跳过。
2. `cpu0_main.c` 中原本"车停下后视野里重新出现线就自动起步、不用手动按键"的设计（注释仍在）
   在本次重构中失效：`track_fault` 锁存 + `line_ring_armed=0`，自动重启条件 `!track_fault` 永远不成立。
   若希望"停车 + 自动重起步"（而不是现在的"爬行找回 + 超时人工重发车"），需按上表 #3/#4 一起改。
3. 有效性门限本身仍偏严（`valid>=20 && near>=6`）：爬行找回只治"短暂丢线"，
   若实际丢线经常超过 200ms，应回到 `vt_analyze` 放宽门限或改进转弯期的链式播种。
