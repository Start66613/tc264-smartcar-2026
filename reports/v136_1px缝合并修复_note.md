# v136：1px 缝合并 —— 修复"中线整条竖直指向赛道外白色地板"（2026-10-11 06:37 已烧 HEX CA8577E0）

## 一、用户报告的现象（存帧 0605，红圈=大圆环左上"连接转弯"）
「中线对着远处赛道外面接近白色（白色的度不一样）的地板，可能是误把地板识别成了赛道，
但是中间还隔着一点蓝色」。

## 二、存帧逐行定量诊断（tmp/frame_saved_0605.bin，固件同源代码静态回放）
- 二值化：一级 Otsu=179 → 亮类 83% → 二级 Otsu=241（蓝白分离正常）；
- 逐行白段实测：**y=81~85 每行都有一个 1px 的浅缝**（灰度 224~247，仍高于阈值 241 → 被判黑），
  把"赛道白块"切成两段（如 y=85: 26..126 + 128..161，缝在 x=127）；
- 逐行追踪的"双边界连续性"检查（两端同时落在上一行 ±12px 窗口）在这 5 行全部失败，
  **连续 3 行失败即 break**（vt_take_row miss>=3）→ 追踪链在 y≈85 处断裂；
- 上方 y=28~85 **58 行全部没有测量**，第 3 遍只能按"最近可信行(y=86)"竖直外推 →
  整条中线竖直落在 x=93，从近处（赛道）一路插到画面顶部（**赛道外的白色地板**）；
- 后果：mid=93（≈直行）→ 车"以为前方直行"；实测行数只有 20，模型行 63。

## 三、修复方案（v136，一处改动）
**窄缝合并**：同一行内与上一白段只隔 **1 像素** 的段，并回上一段（只延 r 端）。
两道护栏：① 合并后宽度必须仍 ≤ VT_SEG_MAX(150) 才生效（超宽不并，本帧 y=56 的
34..53+55..186=153px 保持原样）；② 只并 1px 缝——物理上这是反光/接缝/噪声（≈2mm），
不是道路分界（路口蓝缝实测 ≥8px、环内蓝洞 25px，均不受影响）。
