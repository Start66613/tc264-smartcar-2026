## 二、材料 A：caipingjiang/smart_car（第十八届）

### 2.1 视觉：**整帧不二值化**，边线 = 归一化对比度判据（最重要）

`my_image.c::find_middle()` L187-261，左右边界各用一个**双项加权判据**（L212-221 / L241-250）：

```c
a = j; b = a - 5;                       // 左扫：向左跨 5px
value_1 = 100*abs(img[i][a]-img[i][b]) / (img[i][a]+img[i][b]+1);   // ① 局部梯度（归一化）
value_2 = 100*abs(img[i][b]-white_value) / (img[i][b]+white_value+1); // ② 与参考白偏离
if (value_1*0.6 + value_2*0.4 > x_threshold /*=15*/) { boder_L[i]=b; break; }
```

- **参考白 `white_value` 是滚动自适应**（`find_longest` L124）：
  `white_value = 0.7*130 + 0.3*find_white_point(image)`，其中 `find_white_point()`（L63-84）在**图像中下部 20×8 采样块**（行 84~104、列 100~108）取灰度 >55 的均值，采不到就返回 120。
  → 每帧**慢速跟随光照**，而不是每帧重算一个整幅阈值。
- **纵向也同法**（`find_longest` L128-162）：每 2 列从底向上找第一个"偏离参考白超过 `y_threshold=22`"的点，作为该列的白区顶端。
- **推论（对我方关键）**：这条路线的边界判据**从来不是"一个整幅阈值"**，而是"**该点 x±5 邻域的局部反差** + **与当前参考白的偏离**"。整幅光照漂移被 ① 归一化、被 ② 的慢跟随吸收。这解释了为什么它**不需要 Otsu、不需要二值化**却能在蓝白赛道稳定取边。
  这与深挖4 的 SJTU 结论同源，但**更彻底**：SJTU 仍是"局部窗口阈值 + 二值化"，caipingjiang **根本不做二值图**（`otsu()` 在 L819-865，注释明确"**以下为未使用**"）。

### 2.2 全白列检测 = 十字/环口的天然探测器

`find_longest` L126-172：
- 对每列向上扫，若**扫到最上行仍为白**（`value_2<y_threshold && a<=2`）→ 记为"满屏白列"，累计 `highest_count`、平滑求 `high_sum/highest_count`。
- L168-172：`if(|high_sum/highest_count - index| < 40) { *longest = 0; *index = 均值; }`
  → **一旦画面出现成片的"通到顶的白列"，直接把 `longest` 打成 0**（"我看到的最远点=无限远"），并把锚定列改到白列群的均值中心。

我方对应的做法是 `cam_bin_suspect`（白占比 >72%，`cam_image.c` L377）+ `all_white` 分支（`track_core.c` L519-538，用上一帧中心硬顶 2s）。**差别**：caipingjiang 的"满屏白列"是**列级**判据（哪几列通到顶、均值在哪），比我们的**帧级占比**更精细——它能同时给出"这是路口/环口"**和**"口子的横向中心在哪"。我方 all_white 分支只能"沿上一帧中心直走"，**没有横向中心信息**。

### 2.3 环岛状态机 `roundabout()` L613-704（5 态）

宏（L534-541）：
```
track_wide_limit   = W*H*4/15 = 6016   // 十字
track_wide_limit_2 = W*H*4/16 = 5640   // 环岛
start_height=H/3, end_height=2*H/3     // 宽度统计带
cross_longest_limit = 10 ; cross_slope_limit = 12
lose_point_num_limit_1 = 65 ; lose_point_num_limit_2 = 10
```
宽度 `track_wide` 在 `cross()` L555-558 里累加：`Σ(boder_R[i]-boder_L[i])`（行 H/3 ~ 2H/3）。

**态 0 → 1（进环检测 + 方向判别）L615-682**：
```c
if (track_wide > 5640 && longest < 10) {
  // 左环岛
  if (lose_L > 65 && lose_R < 10 && curvity_calculate(boder_R,&longest) < var_limit2) { flag=1; dir=-1; }
  // 右环岛
  else if (lose_L < 10 && lose_R > 65 && curvity_calculate(boder_L,&longest) < var_limit2) { flag=1; dir=+1; }
}
```
- **方向判别 = "哪一侧丢线多"**：左环岛时左壁消失（左丢线多），右环岛时右壁消失。
- **三重与门**：① 宽度突增（>5640，即赛道被环口"撑宽"）② 最长白列塌到顶部（<10）③ 单侧丢线 >65 且另一侧几乎不丢（<10）。
- 第四重是**另一侧边线的直线度**（见 2.4）——保证"环口外那侧仍是直道"。

**态 1 → 2（L684-687）**：`roundabout_flag==1 && turn_flag==1` —— 车按陀螺转过 90°（`car_control.c` L550-567：`angle_turn=-(dir*180)`，`while(|Zdata-angle_now-angle_turn|>8)` 等待，容差 8°）**之后**才推进，避免"刚进环就误判"。

**态 2 → 3（出环检测）L688-695**：
```c
if (longest < 5 && (dir>0 ? index < W/2 : index > W/2) && roundabout_card_releaseFinish) flag=3;
```
- **出环判据 = 最长白列重新通到顶（longest<5）**，**且**该白列锚定列 `index` 落在**与环方向相反的一侧**——`dir>0`（右环）要求 `index < 中心`。
- L690 原注释直白写了这一条的作用：`(index < roundabout_dir*W/2) --> 防止进入环岛刚转向时识别为出环岛`。
- 这是**廉价的"反向校验"**：进环瞬间也会出现"白列通顶"，加一个"锚定列在环的哪一侧"就能区分进/出。

**态 3 → 4（L696-699）** 等陀螺转向完成；**态 4 → 0（L700-703）** 回到 `Image_Mode==0` 时清标志。

> 注意：这条路线**没有"环内补线"**——环内它靠**陀螺 180° 定角 + 图像模式切换**直接掉头（该届环岛要求"进出同一口"，故必须掉头）。控制细节（拣/放卡片）**与我方任务无关，不采纳**；**采纳的是"检测+判别+防误判"的结构**。

### 2.4 直线度判据 `curvity_calculate()` L352-405

- 取边线两端各 5 行均值 → 拟合一条直线 → 返回**残差平方和 `var`**（`Σ(slide_line[i]-x)²`）。
- 用法：`curvity_calculate(boder_L/...) < var_limit2` 表示"**这条边线很直**"。
- 意义：环口外那一侧仍是**直道**，用"对面是直线"来排除急弯（急弯两侧都弯）。
- 我方对应：`track_core` 的 `straight_left/right`（`open_n>=20 && straight_占比>=75%`，L592-593）——**语义等价但更粗**（我方式"占比"，它是"残差方差"，能区分"整体微弯"与"折线"）。深挖3 里 NEUQ 的"直线拟合度评分"被查实是死代码；**caipingjiang 这个是活的**，可作我方"直线度"判据的升级参考。

### 2.5 误差（`slope()` L281-342）

```c
sum1 = Σ(boder_M[i] - middle);            // 中线相对图像中心的偏差
sum2 = Σ(MT9V03X_H - 10 - i);             // 行权重和
result = 50 * sum1 / (sum2+1);  限幅 80
```
- 与"加权平均偏差"同构；**当 `longest>SHORTEST`（丢线/冲出）时直接 `return lastresult`**（L287）——**丢线保持上次误差**，我方是 `mid<0` 保持上次 `filtered_error`（L735-736），**思路一致**。
- `longest<15` 时（近十字/环口）**跳过顶部 30 行**只算近处（L291-298），避免远处白带污染误差。

### 2.6 边线矫正（并级 PID）`sideline_correct` L417-449 + `my_motor.c::roundabout_move` L164-182

- 采 `boder_U`（顶边界）在 `middle±30` 共 60 列。
  `angle = Σ前10 - Σ后10`，`distance = (Σ前10 + Σ后10)/2`。
- 两路并行 PID：`out1 = Kp1*angle + Kd1*Δangle`（倾角），`out2 = Kp2*(430-distance) + Kd2*Δ`（距离）。
- 用途：**横向平移对齐**（拣/放卡片用），**与我方无关**，但它演示了"用顶边界形状同时解算车身**航向误差 + 横向偏移误差**"——这是我方目前没有的能力（我方只有中线偏差一个量）。

### 3.1 直道校验 `line_lockup()` L31-59（被反复复用）

```c

av = total/40;
```

### 3.2 进环三重判据 `round_deal()` L374-555

以右侧为例（左侧镜像）：

4. **跳变点距离窗口** L409-418：从拐点往上找"下一点黑、上一点白"的跳变行 → `tiaobian_right = i - right_guai_point`，要求 **`15 < tiaobian < 27`**。

### 3.3 漏判/歪入环找回 `right_ring_find_again()` L223-283 / `left_ring_find_again()` L287-347

**这是本轮最有价值的一段**，因为它直接针对"主判据没触发"的兜底：
```c
// 1) 找"连续丢线"起点（3 行间隔都丢）
for(i=8..45) if(right_pos[i]==1 && right_pos[i+2]==1 && right_pos[i+4]==1) { diu_hang_num = i+4; break; }
// 2) 在丢线区上方找"凸点"：前后小、中间大
if(diu_hang_num>8)
  for(i=8..45) if(right_pos[i]<=right_pos[i+3] && right_pos[i+3]>=right_pos[i+6]) { tuqi_point_hang=i+2; break; }
// 3) 从凸点向下找第一个丢线行 → flag_num（入环行的上界）
if(tuqi_point_hang<=40 && tuqi_point_hang!=0)
  for(i=tuqi_point_hang;i>8;i--) if(right_pos[i]==1) { flag_num=i; break; }
// 4) 统计凸点下方"近边"行数：入环多、出环少 → 小环多、大环少
if(flag_num!=0 && tuqi_point_hang-flag_num>10)
  for(j=tuqi_point_hang;j<50;j++) if(right_pos[j]<10) anther_diuhang_num++;
// 5) 三重确认：凸点-丢线跨距 >10 且 对面直线 且 近边行数>=4
if(flag_num!=0 && tuqi_point_hang-flag_num>10 && line_lockup(Bline_left,129)==1 && anther_diuhang_num>=4)
  { ring_right_flag = 1; zhidao_count_flag = 0; }
```
- **适用场景**：`round_deal` 里 `right_guai_point==8`（即"**不在环路上，或者环路漏判断**"，L395-398 原文注释）→ **斜着入环/漏判**时启用。
- **"入环多出环少 → 小环多 大环少"**（L270、L334 注释）是一句**几何经验**：凸点下方近边行数的多少，反映环口张开程度，可粗判环大小。
- 对我方意义：**v133"全程未触发"、v134 后靠"±20~30px 变体搜索"硬扛的鲁棒性短板**，正是这类"第二套找回逻辑 + 相对判据"要解决的问题。caipingjiang 与 13届 都用了**相对判据（丢线侧比较、与均值比较）**，我方是**绝对行号+像素窗口**模板（`y41-56`、`rs>=140`），这是深挖3/4 已指出的同一个病根。
- **纪律提醒**：找回逻辑里用了 `zhidao_count_flag`（直道计数）等外部状态，**只抄结构不抄数值**。

### 3.4 环大小识别 → 打死量自适应 `recognition_size()` L976-996 + `get_guai_val()` L998-1011

```c
void recognition_size(void)  // 从黑点起点沿同侧列向下数黑点
{ for(hang=black_point_start; hang<60; hang++){ if(get_img_point(hang,lie)!=0) recognition_B_num++;
                                                if(recognition_B_num>5 && get_img_point(hang,lie)==0) break; } }
int get_guai_val(void){ return (recognition_B_num>=12) ? 10 : 30; }   // 大环→打死10；小环→打死30
```
- **黑点数 ≥12 → 大环 → 转向打死值 10（缓）**；否则小环 → 30（急）。
- 我方 `big_ring.c` 环内是固定 `BR2_TURN_BIAS=30`（L33）。**可加"环大小 → 偏置/持续时间自适应"**（S12），但需先能稳定判别大小。

### 3.5 宽度变化 → 切点检测 L527-553

```c
if(ring_left_flag||ring_right_flag){ if(get_line_weight(5,15) > 70) ring_weight_change_flag=1; }  // 赛道变宽
if(ring_weight_change_flag){ if(get_line_weight(5,15)<=68 && get_line_weight(25,35)>=70)
                                ring_fill_line_flag=1; }   // 变窄→ 到达"直道与圆环的切点位置"
```
- `get_line_weight(start,end)`（L200-221）：区间内赛道宽度均值（丢线行按 80 计权）。
- **语义**：进环后赛道先"变宽"（环口撑开），再在某个行区间"局部变窄" → 那个位置就是**直道与圆弧的切点**，即**最佳补线起点**。
- 这是一个**纯宽度**的"进环进度"参考，与我方"视觉锚点"互补；**不需要陀螺，也不需要模板**。

### 3.6 出环：折点 + 补线 + 一致性退出

- **出环折点 `get_out_ring_zhedian()` L825-903**：同时从"**实际点数组**"（丢线/折点）和"**矫正后数组 `Bline_*`**"两处找折点，取**更靠前（行号更小）的那个**（L850-851 注释"返回一个最小的，才是最真实的"），并写 `valid_line` 作为"折点前有效行"。
- **出环下方补线 `out_ring_under_find_line()` L557-592**：只处理**顶部 5 行**，从中间向左（40→80）找"黑→白"跳变写 `left_pos`，再从中向右（40→0）同理写 `right_pos`（找不到就钉 79 / 1）。→ **出环上方那几条"看不见的边线"用局部跳变硬补出来**。
- **出环判定 `find_out_ring_flag()` L596-677**：出环侧**附近丢线、远处不丢线** + **另一侧边线在区间内与均值偏差 ≤10 的行数 > (end-start-10)**（近乎"全部一致"）→ `out_ring_ok_flag=1` 并 `ring_clear()`（L737-752，一次性清零全部 11 个环岛标志）。同时 `Shi_zi_flag`（十字）在役时**直接 return 0**（L603-606）——**元素互斥**。
- **`add_under_hang()` L679-715**：要求近 5 行左右边线均值分别接近 71 / 13（±5）——典型的**硬编码坐标先验**，**只作"结构（用近端边线均值做闸门）"参考，数值不可抄**。

## 四、我方现状核对（v142）——一个必须先说清的事实

读 `track_core.c` 本轮发现：**我方实际存在两套环岛逻辑**。

1. **`big_ring.c`（在役）**：三锚点（`br2_detect_arm/mouth/exit`，L52-98）状态机 `OFF→ARMED→TURN→LOOP→STRAIGHT→TAIL→DONE`（L133-163），**硬编码右环**，环内 TURN/STRAIGHT 注入固定 mid（L165-176），8s 保险（L122-127）。v141 加了左转协调（`mid<BR2_LEFT_SOFT_MID` → 改右转，L174-182）。
2. **`track_core.c::element()`（第二套，被 big_ring 旁路）**：L630-663 是一个**完整的左右通用环岛 FSM**：
   ```c
   enum {VT_NORMAL,VT_RING_BEGIN,VT_RING_IN,VT_RING_RUN,VT_RING_OUT,VT_RING_END,VT_CROSS};  // track_core.h L100
   opening = (open_left>=600 && corner_left && straight_right) ? 1 :        // 左开口 → 左环
             ((open_right>=600 && corner_right && straight_left) ? -1 : 0);  // 右开口 → 右环
   ... rel=abs(yaw10-ring_yaw0) 按陀螺角推进：REL 600 → IN，2300+fork → OUT，2800 → END
   vt_edge_mode(): VT_RING_IN/OUT → 按 ring_direction 返回 1/2（左右边界模式）
   ```
   而且 `element()` **确实被调用**（`track_core.c` L692 `else if(v->valid)element(c,v,yaw10);`），但 `big_ring` 一旦注入 `v->special_route=1`，L681/L691 就把帧导向"旁路 element、清 phase"。

**结论**：我方"四环双模板/左环识别"**不是从零开始**——`element()` 里已经有一套**形状化左右判别（开口侧 + 角点 + 对面直线）+ 陀螺分段推进 + 按方向切换 `edge_mode`** 的骨架，结构与 CQU 的陀螺分段、caipingjiang 的"丢线侧判别"**同构**。真正的问题是：**它没在役，且环岛职责已被 big_ring 独占**。这改变了 S7 的写法（不是"新写左环判别"，而是"**把已有的开口侧判别接给 big_ring 做方向**"）。

> 备注（供你决策，未改代码）：同时存在两套环岛 FSM 本身是**维护风险**——建议在报告外单独排一次"环岛职责收敛"的评审；本报告不给改动建议，只登记事实。

## 六、一句话总结

**材料 A（caipingjiang）给的是一把新钥匙**：整帧**不二值化**、边线靠"局部归一化梯度 + 慢跟随参考白"——如果说深挖4 的 SJTU 是"把整幅阈值换成局部窗口"，那 caipingjiang 就是"**根本不需要阈值**"。这是"盲区全白"最彻底的对策，而且它的**通顶白列检测同时给出了口子的横向中心**，正好补上我方 `all_white` 只能"沿上帧中心硬顶"的短板。

**材料 B（13届 roundadout）给的是防误判的完整链条**：6 重进环与门、**"漏判/歪入环"找回支路**、起跑线过滤、宽度→切点、出环折点+下方补线。它几乎每一项都对着我方 v133/v134 暴露过的短板，而且**判据全是相对的**（与均值比、与丢线行比），不绑标定——这正是我方"绝对行号+像素窗口"模板最缺的品质。

**还有一个必须先处理的事实**：我方 `track_core.c::element()` 里**已经躺着**一套左右通用环岛 FSM（开口侧判别 + 陀螺分段 + 按方向切换边缘模式），与 CQU/caipingjiang 的判别方式同构；它现在被 `big_ring` 旁路。**所以"左环识别"不是从零写，而是"把已有判别接给在役模块"**——这同时暴露了"两套环岛 FSM 并存"的维护风险，建议单独评审。
