# run15 不进环 —— 根因（顺序竞态）与 v148 影子验证（2026-10-11 18:30）

## 现象
run15（v147，232 帧）：车正常出发、巡线正常，但到环岛入口不进环，
一路直行走掉，状态机卡在"武装"（P1/ARMED），此后全程静默。

## 根因（逐帧实录）
环岛入口三类特征混杂出现，本轮"口"比"武装"先凑齐确认次数：

```
f135-136  口特征(点2) 命中2次（165ms 确认窗口内）→ 当时还在 OFF（未武装）→ 证据被丢弃
f138      武装特征(点3) 确认 → 进入 P1(ARMED)
f140 之后  口特征再未出现（车已开过入口区）→ 永远等不到口 → 全程卡 P1
```

状态机硬性序列="先武装(P1) → 再看口(P2)"。这轮顺序颠倒（先口 → 后武装）→ 口的确认被浪费。
**三轮对比**：run12 武装先→口后 ✓进环；run14 武装+口几乎同帧 ✓进环；run15 口先→武装后 ✗卡死。
→ 不是检测器失效，是"确认顺序"的竞态（哪边先凑齐 2 次命中靠运气）。

## v148 修复方案（影子验证已过，未动工程）
- **思路**：OFF 阶段跟踪"口的预确认"（2次命中/165ms，与正式确认同标准）；
  武装确认的瞬间，若 1.2s 内口刚预确认过 → 不再等待，直接进环（TURN）。
- **范围**（全部在 big_ring.c/h）：
  - `big_ring.h`：+宏 `BR2_PREMOUTH_WIN 1200u`；+字段 `pre_mhits/pre_mstamp0/pre_mstamp`
  - `big_ring.c`：OFF case 增加预确认跟踪；武装路径增加"迟到补救"分支；enter() 清预确认状态
